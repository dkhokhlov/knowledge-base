# Testing

A regular pytest suite in `tests/`. The bash test scripts are wrapped by one
runner, `tests/test_runner.py` (one test function per `.sh`, each with its own
in-file marker + docstring); the python unit tests are separate native modules.
Tests are classified into tiers by env need, selected by marker, one make target
per group. For operations and configuration see [operations.md](operations.md);
for the full tier → marker → target table, the iso-fixture model, and how to add a
test see [tests/README.md](../tests/README.md); for the architecture and trust
model see the [README](../README.md).

## Tiers + markers

One criterion: *a test must not contaminate the env for subsequent tests; if its
effects are hard to recover, it gets its own isolated (iso) env*. The iso env is
**clean = exactly the prod env**; the only diffs are `KB_HOST` (an auto-picked
port) + the ephemeral `KB_API_KEY` (file-based in the clone `.env.local`). No env
hacks or workarounds.

| Marker | Meaning | Needs |
|---|---|---|
| `unit` | python unit test (stdlib `unittest`, no stack) | nothing |
| `integration` | bash system test against the LIVE stack, read-only | `make start` |
| `iso` | isolated test against a throwaway clean-prod stack (`scripts/lib-e2e-env.sh`) | nothing (self-isolates; GPU/RAM: a 2nd stack) |
| `shared` | cross-cutting tag: the `iso` tests that share ONE session-provisioned stack | — |
| `long` | cross-cutting tag: long-running (real-corpus drain, at-scale) | patient run |

`shared` and `long` are cross-cutting tags carried ALONGSIDE the primary group (a
test can be `iso` AND `shared`, or `iso` AND `long`).

## Prerequisites

The live-stack tests (`integration`) need the stack up (`make start && make
health`) and keys in `.env.local` (see `.env.local.template`):

- `OPENWEBUI_FIRST_USER` / `OPENWEBUI_FIRST_PASSWORD` — the first (admin) [Open WebUI][open-webui]
  user, generated by `make bootstrap` (`admin@${KB_DOMAIN}` + a random password; `KB_DOMAIN`
  is in `.env`, default `local.test`; overridable via `make bootstrap KB_DOMAIN=<domain>`). `test_03` signs in to get a JWT.
- `OPENWEBUI_ADMIN_API_KEY` — the admin key (a valid `KB_API_KEY` for the api-gateway); provisioned by `make api-keys`. `KB_API_KEY` (a non-admin user key) comes from `make users-create`, or from the ephemeral test user provisioned by the iso fixtures (`iso_env` / `iso_env_named` in `tests/conftest.py`).

The `iso` tests self-isolate: they provision their own throwaway clean-prod stack
+ ephemeral user, so they need neither a running live stack nor a pre-provisioned
`KB_API_KEY`.

## Run the suite

| Target | Selector / deps | Runs |
|---|---|---|
| `make test` | `test-unit` + `test-live-RO` | `unit` + live-RO (`test_01/02/03`) |
| `make test-unit` | `-m unit` | the python UTs (no stack) |
| `make test-live-RO` | `-m "integration"` | live-RO (`test_01/02/03`; needs `make start`) |
| `make test-iso` | `test-iso-shared` + `test-iso-single` | all short iso (shared + single) |
| `make test-iso-shared` | `-m "iso and shared"` | the 9 shared-iso tests (one session stack) |
| `make test-iso-single` | `-m "iso and not long and not shared"` | the named own-iso short tests (`test_12`) |
| `make test-long` | `test-iso-long` | long iso (`test_08` + `test_09`) |
| `make test-iso-long` | `-m "iso and long"` | long iso (`test_08` + `test_09`) |
| `make test-output` | `python3 tests/test_output_json.py -v` | standalone JSON-schema UT (no stack) |

`make test` runs the `unit` tests + the `integration` tests (`test_01/02/03`,
read-only against the LIVE stack — needs `make start`). The `iso` tests
self-isolate (throwaway clean-prod stack via the `iso_env` / `iso_env_named`
fixtures, auto-picked port, never touch the live stack): `make test-iso` (the
shared + single short tests) and `make test-long` (`iso long` = `test_08` +
`test_09`). Run a raw selection with `python3 -m pytest -m <expr>`.

`test_09_gdrive_index` is the comprehensive at-scale e2e (`iso long`): clean-all +
image rebuild + preflight + real rclone gdrive corpus + the in-clone suite (unit +
live-RO 01/02/03 against the fresh stack) + the full real-gdrive drain. Its
`iso_env_named("gdrive", at_scale=True)` fixture provisions via
`e2e_provision_at_scale` (the destructive variant); the shared/single iso tests use
`e2e_provision` (clean-prod). Enter it with `make test-long` (or `.venv/bin/python
-m pytest -m "iso and long" -k test_09_gdrive_index -v`). The gdrive index path is
also covered fast + deterministically by `test_11` against a committed fixture set;
chunk quality is covered by `test_13` against generated per-type fixtures.

## Notes

- Contamination: the `integration` tests are read-only except `test_03` (one stateless chat completion). The `iso` tests run against a throwaway clean-prod stack, so their writes never reach the live env. The `iso`+`shared` tests self-clean (traps delete temp KBs/files) so the one shared session stack stays clean across them. `test_07` rollback case starts an isolated api-gateway (`docker compose run`) with the test-only `KB_TEST_PROVISION_FAIL_AFTER_CREATE` flag to force a failure after user creation; if that run mechanism is unavailable it is skipped (verify it exercises, not skips, on the host).
- `test_09` is `iso long`, the comprehensive at-scale e2e. It does NOT SKIP: the `iso_env_named("gdrive", at_scale=True)` fixture always provisions the gdrive KB + syncs the corpus (`e2e_provision_at_scale`: clean-all + image rebuild + preflight + rclone + `make ci`), or provision fails first and the body never runs. A missing `GDRIVE_KB_ID` or empty corpus is a hard fail (`require_env` / `completed < source`), not a silent pass. The body runs the in-clone suite (unit + live-RO 01/02/03 against the fresh stack) then the full real-gdrive drain (`POST /index` + poll `GET /status` + failure audit + semantic search). Enter it with `make test-long` (or the focused `pytest -m "iso and long" -k test_09_gdrive_index -v`).
- `test_10` SKIPs when OCR is disabled (`OCR_ENABLED!=true`; unset defaults to enabled). `test_11` uses api-gateway (`POST /index` + `GET /status` with the `path` param), a core service (not a sidecar), against committed `gdrive/.tests/` fixtures (a dot-dir the full gdrive walk skips, so the real gdrive KB is never contaminated); it SKIPs when `gdrive/.tests/` has no allowlisted fixtures. `test_13` audits the committed fixtures at `gdrive/.tests/chunkq/` (tracked; regenerate with `python3 tests/fixtures_chunkq_gen.py --out gdrive/.tests/chunkq` — the test itself only re-derives the manifest oracle via `--manifest-only` and writes no file). `test_13` is `iso shared` (runs under `make test-iso-shared`); it uses its own `CHUNKQ_WAIT` budget, not the at-scale `GDRIVE_TEST_WAIT`. Text-type chunkq extraction failures are hard fails; binary-type failures are hard fails with OCR on and notices with OCR off; all 10 types are audited with OCR on (the iso env provisions `OCR_ENABLED=true` by default).
- Each bash script sources `tests/lib.sh` (env loader, pass/fail counters, stack-up guard) and exits non-zero on any failure. The iso fixtures (`tests/conftest.py`) own isolate + provision + outcome-branched teardown (test passed → `e2e_down` removes the clone; failed → `e2e_stop_docker` keeps it for inspection; flush with `make clean-tests`).
