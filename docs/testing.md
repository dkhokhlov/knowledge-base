# Testing

System integration tests in `tests/` exercise the running stack over HTTP.
For operations and configuration see [operations.md](operations.md); for the
architecture and trust model see the [README](../README.md).

## Prerequisites

The suite needs the stack up (`make start && make health`) and keys in
`.env.local` (see `.env.local.template`):

- `OPENWEBUI_FIRST_USER` / `OPENWEBUI_FIRST_PASSWORD` — the first (admin) [Open WebUI][open-webui]
  user, generated by `make bootstrap` (`admin@${KB_DOMAIN}` + a random password; `KB_DOMAIN`
  is in `.env`, default `local.test`; overridable via `make bootstrap KB_DOMAIN=<domain>`). `test_03` signs in to get a JWT.
- `OPENWEBUI_ADMIN_API_KEY` / `OPENWEBUI_USER_API_KEY` — admin + agent keys (valid `KB_API_KEY`s for the kb-gateway). Provisioned by `make api-keys`.

## Run the suite

```
make test
```

`make test` runs all `tests/test_*.sh` scripts and exits non-zero if any fail.
It skips `test_09_gdrive_index.sh` (the full real-gdrive drain — slow, coupled
to the live rclone-synced corpus) with a notice; that drain runs under
`make test-e2e` only. The gdrive index path is covered fast + deterministically
in `make test` by `test_11` against a committed fixture set.

## Notes

- The tests are read-only except `test_03` (one stateless chat completion), `test_04` (creates a KB + file, then deletes both on exit), `test_05` (admin creates a temp KB + file + `*` read grant, then deletes all three on exit), `test_06` (writes to a temp agent group, then clears it), `test_07` (creates temp OWUI users, then deletes them via `DELETE /api/v1/users/{id}`), and `test_08` (creates a throwaway OWUI user + agent group via the gateway, then forgets the group + deletes the user).
- `test_07` rollback case starts an isolated kb-gateway (`docker compose run`) with the test-only `KB_TEST_PROVISION_FAIL_AFTER_CREATE` flag to force a failure after user creation; if that run mechanism is unavailable in the environment it is skipped (verify it exercises, not skips, on the host).
- `test_09` is not part of `make test` (the Makefile skips it with a notice); it runs the full real-gdrive drain under `make test-e2e`, which invokes it by path after the fresh `gdrive-sync`. It still SKIPs (passes with a notice) when run standalone with `GDRIVE_KB_ID` unset or `./gdrive` empty. `test_10` SKIPs when OCR is disabled (`OCR_ENABLED!=true`; unset defaults to enabled) — so `make test` runs clean in a bare environment. `test_11` uses kb-gateway (`POST /index` + `GET /status` with the `path` param), a core service (not a sidecar), against committed `gdrive/.tests/` fixtures (a dot-dir the full gdrive walk skips, so the real gdrive KB is never contaminated). The full clean-state run that provisions the OCR sidecar + the gdrive KB is `make test-e2e` (destructive: wipes `./data` + re-provisions; runs `make gdrive-sync`, then `make test`, then `test_09` by path).
- Each script sources `tests/lib.sh` (env loader, pass/fail counters, stack-up guard) and exits non-zero on any failure.
